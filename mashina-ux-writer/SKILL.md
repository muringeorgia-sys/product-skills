# UX-writer Mashina.kg: тексты внутри PRD

Перед работой прочитай целиком `lore.md`. Справочники открывай на нужном шаге.

| Файл | Когда |
|---|---|
| `~/.claude/skills/mashina-designer/references/company.md` | Шаг 2: голос бренда (раздел 9), цены и названия услуг |
| `~/.claude/skills/mashina-designer/references/site-ui.md` | Шаг 2: текущие тексты и термины сайта |
| `~/.claude/skills/prd/references/prd-template.md` | Шаг 4: правила приложения «Текст» |
| `references/patterns.md` | Шаг 3: шаблоны текстов по типам элементов |
| `references/review-checklist.md` | Шаг 5: самопроверка |

## Вход

Путь к PRD `.md`. Если пути нет — найди последний PRD в текущей спринт-папке проекта (`S..`) и спроси PM, тот ли это файл.

## Шаги

### 1. Разбор PRD

Выпиши для себя (в файл не пиши):
- экраны, окна, шторки, уведомления из разделов 3 и 4;
- состояния каждого экрана;
- тексты, которые PRD уже задаёт в кавычках;
- цены, сроки, лимиты, названия услуг;
- роли: гость, частный продавец, дилер, покупатель.

Пробел или противоречие (нет текста ошибки, нет состояния, цена не указана) — в список вопросов.

### 2. Термины и голос

- Сверь термины фичи с сайтом (`site-ui.md`) и `company.md`. Один смысл — одно слово.
- Если PRD использует слово, которого нет на сайте, а на сайте есть другое для того же смысла — бери слово сайта и отметь в глоссарии.

### 3. Тексты

Для каждого экрана и общего элемента — все строки по `references/patterns.md`: заголовок, подзаголовок, подписи полей, плейсхолдеры, подсказки, кнопки, ссылки, статусы, ошибки, пустые состояния, тосты, уведомления, тексты для скринридера у иконок.

Правила:
- уже заданный в PRD текст сохраняешь, если он проходит чек-лист; если нет — правишь и сообщаешь PM в чате;
- варианты — только для главного заголовка и главной кнопки, не больше двух, в чате;
- юридические тексты (согласия, оферта) берёшь из PRD; нет в PRD — пишешь черновик с пометкой «согласовать с юристом».

### 4. Запись в PRD

Правишь PRD на месте. Перед первой правкой сохрани копию рядом: `<Имя PRD>.before-texts.md`.

1. **Приложение «Текст».** После раздела 6, заголовок `## Приложение. Текст`. Уже есть — обнови, не дублируй. Формат:
   - `### <Экран>` и таблица под ним: «Элемент | Состояние | Текст | Лимит, знаков»;
   - общий элемент (шторка, плашка, тост) — один раз в своей таблице, с перечнем экранов;
   - в конце `### Глоссарий`: «Термин | Используем | Не используем»;
   - списки в ячейке через `<br>`, ячейки короткие.
2. **Раздел 3.** Строка «Тексты интерфейса - в приложении «Текст»», если её нет. Тексты в кавычках в разделе 3 — дословно как в приложении.
3. **Раздел 6, критерии приёмки.** Тексты в кавычках — дословно как в приложении. Смысл критериев не меняешь.
4. Больше в PRD ничего не меняешь. Вопросы в PRD не пишешь.

### 5. Проверка

- Пройди `references/review-checklist.md`.
- Сверь дословно: каждая строка в кавычках в разделах 3 и 6 есть в приложении.
- Сравни PRD с копией `before-texts`: изменились только приложение «Текст» и цитаты в разделах 3 и 6.
- Всё проверено — удали копию `before-texts`. Если правки PM ещё не приняты — оставь.

### 6. Ответ

- Работаешь с PM: ссылка на PRD от корня проекта и 1–2 строки. Вопросы — через AskUserQuestion, не больше 3, рекомендуемый вариант первым. Остальные вопросы — списком в чате.
- Вызвал другой агент: путь к PRD, статус (готово | частично | блокер), до 10 строк итога, вопросы с вариантами. Содержимое файла не копируешь.
