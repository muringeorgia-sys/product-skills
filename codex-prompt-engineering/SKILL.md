# Codex Prompt Engineering

Преобразовывать сырой запрос в прикладное инженерное задание, которое Codex может выполнить безопасно, предсказуемо и с проверяемым результатом.

## Рабочий процесс

1. Выделить факты пользователя, критичные пробелы, ограничения и желаемый результат.
2. Не выдумывать репозиторий, пути, команды, API, архитектуру, критерии успеха или бизнес-логику.
3. Если безопасное рабочее задание возможно, явно обозначить разумные допущения и продолжить.
4. Если пробел меняет разрешённые действия или критерий успеха, задать не более 1–3 критичных вопросов.
5. Классифицировать задачу и выбрать режим.
6. Проверить, помещается ли работа в один обозримый PR. Если нет — сформировать task queue.
7. Собрать prompt из релевантных секций, не добавляя пустые разделы ради шаблона.
8. Проверить prompt по [quality-review.md](references/quality-review.md).
9. Выдать готовый prompt первым; теорию свести к нескольким полезным пояснениям.

## Классификация

Выбирать наиболее узкий тип:

- repository analysis;
- bug investigation;
- bug fix;
- feature implementation;
- refactoring;
- test coverage;
- code или PR review;
- architecture review;
- migration;
- performance optimization;
- documentation или cleanup;
- security review;
- environment setup;
- `AGENTS.md` / project instructions;
- task queue / backlog;
- prompt improvement.

## Выбор режима

| Режим | Выбирать, когда |
| --- | --- |
| `Investigate only` | Нужно понять код или причину без правок |
| `Plan first` | Задача неоднозначная, широкая, рискованная или затрагивает много файлов |
| `Implement` | Результат, scope и критерии завершения достаточно ясны |
| `Review only` | Нужно проверить код, diff или PR без изменений |
| `Goal mode` | Работа долгая и многошаговая, но имеет чёткий definition of done |
| `Task queue` | Общую цель нужно разбить на зависимые PR-sized задачи |

Не смешивать режимы противоречиво. Если prompt требует дождаться подтверждения после плана, прямо запретить редактирование до подтверждения.

## Состав prompt

Включать только применимые блоки:

```text
Task:
[конкретное действие]

Goal:
[наблюдаемый результат]

Context:
[подтверждённый контекст]

Relevant files / areas:
[известные файлы, директории, модули, логи]

Scope:
[что разрешено смотреть и менять]

Out of scope:
[что нельзя менять]

Mode:
[выбранный режим]

Before editing:
- inspect relevant files
- identify existing patterns
- propose a short plan
- mention risks or unknowns

Constraints:
[технические, продуктовые и архитектурные ограничения]

Done when:
[проверяемые критерии]

Verification:
[конкретные тесты, lint, build или manual checks]

Final response:
- summary
- files changed
- important decisions
- diff summary
- verification result
- remaining risks / unknowns
```

Не подставлять несуществующие команды. Если команды неизвестны, поручить Codex определить их по `AGENTS.md`, CI, package-файлам, Makefile или документации и явно сообщить, что удалось запустить.

## Codex-specific правила

- Формулировать одну задачу как issue или обозримый PR.
- Требовать осмотреть релевантные файлы и существующие паттерны до правок.
- Ограничивать изменения минимальным scope; запрещать несвязанный рефакторинг и formatting churn.
- Сохранять публичное поведение, если его изменение не входит в цель.
- Не разрешать новые зависимости без необходимости и обоснования.
- Не разрешать hard-code только ради прохождения текущего теста.
- Всегда задавать проверку результата. Разделять ошибки, вызванные изменением, и посторонние сбои окружения.
- Для параллельной работы разделять задачи по независимым областям; не направлять разные threads на одни файлы или тесно связанную логику.
- Для cloud-задач указывать setup expectations, допустимость установки зависимостей, нужные переменные среды и поведение при недоступных командах. Не включать значения секретов.
- Повторяющиеся правила проекта выносить в `AGENTS.md`, а не дублировать в каждом prompt.

## Справочники

- Для готовых заготовок по типам задач читать [task-templates.md](references/task-templates.md).
- Для создания постоянных проектных инструкций читать [agents-md-template.md](references/agents-md-template.md).

Загружать только справочник, нужный текущей задаче.

## Формат ответа

По умолчанию отвечать так:

```text
Тип задачи: [classification]
Целевой инструмент: Codex
Рекомендуемый режим: [mode]
Допущения: [только если есть]

Готовый prompt:

[готовый prompt для вставки]

Почему структура подходит:
- [2–4 конкретные причины]

Критичные уточнения:
- [только если действительно нужны]
```

Если пользователь просит только готовый prompt, не добавлять объяснение. Если просит оценку, дать балл, конкретные пробелы и улучшенную версию.
