## Обязательная проверка

Проверить:

- Цель конкретна и описывает наблюдаемый результат.
- Понятно, разрешены ли изменения.
- Выбран один непротиворечивый режим.
- `Scope` ограничивает разрешённую область.
- `Out of scope` защищает важные несвязанные области.
- Ограничения относятся к реальному риску задачи.
- `Done when` содержит проверяемые критерии, а не субъективные слова.
- `Verification` использует известные команды или требует обнаружить существующие команды по репозиторию.
- Запрещены несвязанные изменения и formatting churn.
- Требуется изучить существующие паттерны до реализации.
- Финальный ответ сообщает изменения, проверки и оставшиеся риски.
- Факты, пути, команды и API не придуманы.
- Допущения отделены от фактов.
- Задача помещается в один обозримый PR; иначе выбран `Task queue`.
- Повторяющиеся правила предложено вынести в `AGENTS.md`.
- Внутри prompt нет конфликтующих требований.

## Рубрика на 100 баллов

| Критерий | Баллы |
| --- | ---: |
| Ясность цели | 15 |
| Контекст и relevant files / areas | 15 |
| Scope / out of scope | 15 |
| Constraints | 10 |
| Done when / acceptance criteria | 15 |
| Verification | 10 |
| Безопасность изменений | 10 |
| Подходящий режим Codex | 5 |
| Формат финального ответа | 5 |

Не ставить высокие баллы за наличие заголовка без содержательной конкретики.

## Интерпретация

- `90–100` — готов к запуску.
- `75–89` — рабочий, но отдельные пробелы стоит уточнить.
- `60–74` — черновик с заметным риском лишней или неверной работы.
- `<60` — переписать до запуска.

При оценке вернуть:

1. итоговый балл;
2. разбивку по критериям;
3. критичные пробелы;
4. улучшенную готовую версию prompt.

## Частые дефекты

### Слишком широкая задача

Дефект: `Refactor the whole project and improve architecture.`

Исправление: ограничить модуль и наблюдаемую цель или сначала запросить `Plan first`; крупную работу разбить на `Task queue`.

### Нет проверки

Дефект: `Add the feature.`

Исправление: назвать релевантные тесты, lint и build. Если команды неизвестны, потребовать найти существующие команды в проектных файлах и сообщить источники.

### Нет out of scope

Дефект: `Fix checkout issues.`

Исправление: защитить несвязанные UI, pricing, payment integration, API или зависимости — только если такие границы подтверждены контекстом.

### Смешаны разные задачи

Дефект: один prompt одновременно требует исправить баг, мигрировать библиотеку, провести рефакторинг и оптимизацию.

Исправление: разделить на зависимые PR-sized задачи с собственными критериями и проверками.

### Субъективный результат

Дефект: `Make the code cleaner.`

Исправление: назвать конкретный дефект и измеримый результат, например устранение подтверждённого дублирования при сохранении поведения.

### Выдуманные детали

Дефект: указаны предполагаемые пути или команды как факты.

Исправление: пометить их как неизвестные и поручить Codex подтвердить их по репозиторию до правок.

## Decision tree

```text
Неясно, как работает код → Investigate only.
Неясно, что или где менять → Plan first.
Задача узкая, критерии и scope ясны → Implement.
Нужно проверить diff или PR → Review only.
Задача длинная, но definition of done чёткий → Goal mode.
Работа больше одного обозримого PR → Task queue.
Нужно найти причину ошибки → Bug investigation.
Причина или воспроизведение ясны → Bug fix.
Нужно улучшить структуру без изменения поведения → Refactoring.
Нужны постоянные правила проекта → AGENTS.md.
Несколько threads затронут одни файлы → не выполнять параллельно.
```
