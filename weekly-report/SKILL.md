## Правила, которые нельзя нарушать

- North Star одна: **количество активных объявлений** на конец отчётного дня. Данные об активных объявлениях **не брать**: счётчик на главной сайта и снимки (query 268/271) неактуальны. В презентацию North Star не выводить (ни плитки, ни строки). Не делать выводов про динамику активных объявлений.
- **WAU и «долю платящих» из `raw.events` не показывать** (решение 14.09.2026): в `raw.events` не ясно, считаются устройства или люди и есть ли сайт, а доля смешивала бы серверные платежи со всех платформ и пользователей GA. Вместо них - DAU приложений (438) и ARPPU (326). Вернуть можно только после проверки платформ в `raw.events`.
- Redash: смотреть **только дашборды, созданные с 12.05.2026**. Запрос, который есть только на старых дашбордах (например, 93 на дашборде 19), не использовать. Прежде чем взять новый запрос, проверь дату дашборда: `GET /api/dashboards?order=-created_at`, затем `/api/dashboards/<id>` → `widgets[].visualization.query.id`.
- Все обязательные метрики показываются каждую неделю. Порог (`критично` ≥ 15%, `заметно` 5–15%) влияет только на глубину разбора; подробно - не больше трёх-четырёх инсайтов.
- Каждое утверждение - **факт** или **гипотеза**. Совпадение динамики - не причина.
- **Нет данных - не показывать.** На слайдах нет плиток «нет данных», блоков и строк «Пробелы данных», «нужно подтвердить», строк приложения без источника, пометок «план не найден». Слот занимает метрика, у которой данные есть. Пробелы, план и owner - только в ответе пользователю в чате. Это решение пользователя от 14.09.2026 и оно важнее регламента, который требует показывать пробелы.

## Шаг 2. Анализ

1. Пересчитай ключевые проценты руками из абсолютных значений - в презентацию идут только перепроверенные числа.
2. **Инсайты - один слайд, 3-4 карточки, супер конкретные и точные.** Каждая карточка:
   - заголовок - сам вывод с числом или объектом («Весь рост выручки дало промо», «Дилеров платит больше, денег меньше»), не тема;
   - «Факт» - только числа из выгрузок с изменением «число (процент)» к предыдущей неделе и конкретной точкой (день, тип отчёта, тариф), без оценочных слов;
   - «Проверка» - **анализ уже проведён**: что посчитал и какие числа вышли («топ-10 плательщиков дали 156 377 сом против 246 029 (−89 652, −36,4%) — это 59% всего падения»). Гипотезу не выводить: пользователь считает её фактом, который надо проверить, а не показать (решение 22.09.2026). Если причину можно проверить SQL-выборкой - **посчитай сам и покажи результат**, а не пиши «выгрузить и посчитать». Выборка идёт через `/api/query_results` (только SELECT, сохранённые запросы не трогать), полный расклад - в `notes`;
   - «Вывод» - что это значит и что делать дальше, одной строкой. Действие остаётся только то, что нельзя посчитать сейчас («следующую рассылку делать с контрольной группой 10%»);
   - `tip` на отчёт Redash, откуда факт.
   Поля в JSON: `fact`, `check`, `conclusion`. Старая тройка `fact` / `hypothesis` / `action` в `build_deck.js` работает, но используется, только когда проверить нечем.
   Типовые проверки: концентрация выручки - суммы по пользователям и доля топ-10 за оба периода; сдвиг микса - средний чек по `type` транзакций за оба периода; эффект рассылки - та же когорта получателей за неделю до рассылки (когорта `failed` как контроль не годится: там неактивные аккаунты без токена); рост направления - разрез по `product_id` с числом платежей.
   Где искать: разрыв между связанными метриками (платящих больше, а выручка направления меньше; сообщений больше, а регистраций столько же), разовые пики по дням (364 по дням), сдвиг микса (303 по типам отчётов, подписка дилеров - платящие vs средний платёж), конверсии парсера. Если конкретного вывода с числами нет - карточку не делать; если нет ни одного - слайд инсайтов не выводить.
3. **Парсер Lalafo** - считай все показатели (они в `notes` слайда и в чат по запросу):
   - абсолютные: найдено контактов, отправлено сообщений, зарегистрировалось, новых объявлений, количество пополнений, сумма пополнений, количество расходов, сумма расходов, активные пользователи;
   - конверсии: контакт → сообщение (отправлено / найдено), сообщение → регистрация (зарегистрировалось / отправлено), регистрация → новое объявление (новые объявления / зарегистрировалось), сообщение → новое объявление (новые объявления / отправлено), регистрация → пополнение (пополнившие пользователи / зарегистрировалось);
   - на активного пользователя: пополнения (сумма пополнений / активные), расходы (сумма расходов / активные).
   На слайд - 8 главных плиток за неделю к предыдущей: найдено контактов, отправлено сообщений, зарегистрировалось, сообщение → регистрация, новых объявлений, активные пользователи, сумма пополнений, сумма расходов; под плитками - итог с перезапуска 26.08. Режимы объёма: до 07.09.2026 включительно - 700 объявлений в день, с 08.09.2026 - 3000; если объём снова поменяется - добавь режим в `CFG.parserRegimes` со слов пользователя и упомяни в подзаголовке.
4. Спринты: считай задачи по статусам и этапам из таблицы; блокеры - в примечание карточки; что поменялось с прошлой выгрузки - в ответ в чате.

   **Приоритеты CEO - зелёным.** Задачи, которые CEO отметил важными на встрече, лежат в `references/ceo-priorities.json` (ключ Jira, название, дата отметки). `build_deck.js` сам красит их в зелёный (#00B050) на обоих слайдах спринтов - и в списках, и в карточках: совпадение по ключу Jira в полях `jira` и `tag`, без ключа - по названию.   
   ```powershell
   $ppt = New-Object -ComObject PowerPoint.Application
   $p = $ppt.Presentations.Open("<полный путь к pptx>", $true, $false, $false)
   for ($i = 1; $i -le $p.Slides.Count; $i++) { $p.Slides.Item($i).Export("<scratchpad>\render\s$('{0:D2}' -f $i).png", "PNG", 1600, 900) }
   $p.Close(); $ppt.Quit()
   ```
   Посмотри каждый PNG: текст не вылезает и не переносится внутри числа, блоки не налезают друг на друга. Сравни с эталоном `references/deck-reference-2026-09-15.pptx`: макет и порядок слайдов должны совпадать. Частые правки: длинные суммы в плитке - единицы в подпись (`Выручка, сом` / `1,60 млн`); длинный текст карточки - сократить. Исправь, пересобери, перерендери только изменённые слайды.
