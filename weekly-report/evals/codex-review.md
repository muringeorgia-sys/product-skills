# Второе мнение Codex по отчёту CEO

Codex читает текст слайдов и выгрузки и ищет ошибки в числах. Презентацию не правит.

## Запуск

1. Текст слайдов в файл: `node evals/deck_text.mjs <deck.pptx> > tmp/wbr_review/<дата>/slides.txt`.
2. Промпт — `tmp/wbr_review/<дата>/prompt.md` по шаблону ниже: пути к `slides.txt`, финотчёту и выгрузкам Redash и Jira этой сборки.
3. Из корня проекта, механика — как в `~/.claude/skills/prd/references/review.md`, раздел «Второе мнение Codex» (скрипт `codex-companion.mjs`, без `--write`, таймаут 600000 мс):
   ```bash
   node "<codex-companion.mjs>" task --model gpt-6.1-sol --effort xhigh --prompt-file "tmp/wbr_review/<дата>/prompt.md"
   ```
4. Каждое замечание проверь сам по данным. Принимай только подтверждённое. Итог в ответе: «Codex: N замечаний, принял M», отклонённые — строкой с причиной.

## Шаблон промпта

```
Ты ревьюер отчёта для CEO. Ищешь ошибки, текст не переписываешь, файлы не меняешь.
Файлы: <slides.txt>, <финотчёт>, <выгрузки>.
Проверь:
1. Суммы направлений = итог; проценты выполнения и изменения пересчитываются из чисел слайда. Проценты на слайдах округлены до целого, расхождение в 1 сом — не замечание.
2. Числа на слайдах совпадают с выгрузками и финотчётом (финотчёт главнее).
3. Одинаковые периоды и «данные на ДД.ММ» на всех слайдах.
4. Заголовок с цифрой не противоречит числам слайда.
5. Даты релизов и статусы эпиков на слайдах совпадают с заметками и выгрузкой Jira; заголовки-счётчики («в разработке N») — с колонками.
Ответ: таблица «слайд | что не так | где видно | насколько уверен». Нет ошибок — так и напиши.
```
