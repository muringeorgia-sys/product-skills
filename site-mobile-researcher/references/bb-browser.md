# Работа через BB Browser MCP

Эта инструкция относится к плагину `bb-browser-mcp`, серверу `bb-browser`. Схемы ниже проверены 2026-10-04. Перед вызовом используй живую схему установленного инструмента: она имеет приоритет перед примерами.

## Обнаружение и вызов

1. Найди нужные инструменты через `agent_plugins_list_tools` с `serverId: "bb-browser"` и запросом по имени операции. Листинг может быть постраничным: используй `offset`, если нужного инструмента нет в первой странице.
2. Перед первым вызовом операции получи её определение через `agent_plugins_describe_tool`, передав `opaqueId` из поиска.
3. Вызывай `agent_plugins_call` с точным полученным `opaqueId` и аргументами по схеме. Не храни непрозрачные идентификаторы в скилле: они относятся к конкретной установке.

В Claude Code сервер `bb-browser` подключён напрямую (user scope, `node <npm-global>/node_modules/bb-browser/dist/mcp.js`): инструменты доступны как `mcp__bb-browser__browser_*`, bridge `agent_plugins_*` для них не нужен. Пакет `bb-browser` закреплён на версии 0.11.6: начиная с 0.12 MCP-режим из пакета удалён, остался только CLI. Не обновляй пакет без запроса пользователя.

Используй инструменты напрямую, если среда уже предоставляет их с полной схемой. Не подключай другой браузер и не устанавливай зависимости автоматически при отсутствии BB Browser.

## Проверенные операции

| Инструмент | Аргументы | Назначение |
|---|---|---|
| `browser_tab_list` | `{}` | Найти вкладки; не менять существующие вкладки пользователя |
| `browser_open` | `{"url":"https://mashina.kg/"}` | Без `tab` открывает новую вкладку; сохранить возвращённый короткий `tab` |
| `browser_open` | `{"url":"<наблюдаемый URL>","tab":"<tab>"}` | Перейти в своей вкладке |
| `browser_snapshot` | `{"tab":"<tab>","compact":true}` | Читать дерево страницы с номерами `ref` |
| `browser_snapshot` | `{"tab":"<tab>","interactive":true,"compact":true}` | Получить интерактивные элементы |
| `browser_click` | `{"tab":"<tab>","ref":"<ref из snapshot>"}` | Нажать найденный элемент в пределах разрешённого сценария |
| `browser_screenshot` | `{"tab":"<tab>"}` | Получить PNG в формате data URL; это ещё не сохранённый файл |
| `browser_eval` | `{"tab":"<tab>","script":"<JavaScript>"}` | Прочитать ограниченные сведения о текущем экране |

Для ввода, прокрутки, ожидания и закрытия вкладки найди соответствующую операцию и прочитай её схему; параметры не угадывай. После навигации и существенного изменения страницы получай новый snapshot. При слишком кратком дереве убери `maxDepth` или увеличь глубину; отсутствие элемента в обрезанном snapshot не доказывает отсутствие функции.

Пример безопасного чтения контекста через `browser_eval`:

```javascript
JSON.stringify({
  url: location.href,
  title: document.title,
  viewport: {width: innerWidth, height: innerHeight},
  language: document.documentElement.lang
})
```

Не используй `browser_eval` для скрытой отправки запросов, вызовов внутренних API, изменения данных или чтения секретов. Навигация должна опираться на реально найденные ссылки и элементы. Не перебирай предполагаемые маршруты.

## Получение и просмотр скриншотов

1. В собственной вкладке получи актуальный snapshot и контекст экрана. Сними нужное состояние через `browser_screenshot` с явным `tab`. Проверенная схема принимает только `tab`: не добавляй `path`, `fullPage`, размеры или другие непроверенные параметры. Не называй результат снимком всей страницы без подтверждения области захвата.
2. Передай изображение из ответа инструмента на визуальный просмотр. Если ответ содержит image-блок, используй поддерживаемый вывод изображения; если PNG data URL — поддерживаемую передачу изображения либо сохранение и открытие через инструмент просмотра. Не печатай base64 целиком в чат, отчёт или журнал. Если просмотр недоступен, зафиксируй «снимок получен, визуально не проверен» и не делай выводов о внешнем виде по snapshot.
3. Для сохранения используй фактически возвращённое изображение. Если это data URL, проверь формат `data:image/png;base64,`, декодируй его полезную часть в байты и запиши `.png` доступным файловым инструментом в папку подтверждений. Это отдельная операция после screenshot; аргумент `path` у screenshot её не заменяет. Не создавай пустой файл или файл с текстом base64 вместо PNG. Если среда не позволяет безопасно передать байты в файловый инструмент, укажи ограничение сохранения; путь не выдумывай.
4. Имена: `OBS-01_desktop_before.png`, `OBS-01_desktop_after.png`, `OBS-02_mobile.png`; добавляй только реально снятые кадры. До сохранения и выдачи исключи личные данные: выбери безопасную область либо используй поддерживаемое скрытие/обрезку с явной пометкой. Не сохраняй необработанный кадр с чувствительными данными в проект. Не снимай заполненную форму входа. Не дорисовывай интерфейс и не изменяй содержимое продукта на подтверждающем изображении.
5. Проверь существование и непустое содержимое PNG, открой сохранённый файл и убедись, что он читается и соответствует нужной вкладке, состоянию и области экрана. Добавляй ссылку только после этой проверки. В подписи укажи URL, время, платформу, фактический viewport, состояние, позицию/область прокрутки и факт обрезки/скрытия данных, если они применялись. Неизвестные параметры пометь явно.

Если нужен блок ниже первого экрана, прокрути собственную вкладку документированной операцией, получи новый snapshot и снимок. Сохрани несколько подписанных кадров, если целая страница недоступна; не склеивай их с обещанием одного момента времени. Для динамического результата сопоставляй состояния до и после; успешный ответ click не подтверждает появление окна. Скриншот подтверждает видимую область в момент захвата, но не устанавливает причину ошибки или завершение всего сценария.

## Мобильный веб

Для проверки по умолчанию нужны две отдельные записи прохождения: десктоп и мобильный веб. До действий проверь текущий список операций; один fetch или наличие viewport meta tag не является ни одной из этих проверок. Для общей смены viewport используй одного исполнителя последовательно: независимые вкладки не гарантируют независимость настроек браузера.

В проверенном наборе MCP-инструментов нет отдельной операции изменения viewport или эмуляции устройства. Не придумывай `browser_resize`/`browser_emulate` и не выдавай изменение CSS страницы за мобильную проверку.

Если в текущей установке появился поддерживаемый режим изменения viewport, сначала прочитай его схему. Зафиксируй реальный размер окна после переключения; если менялись user agent и touch, укажи это отдельно. Узкое окно подтверждает адаптивную раскладку, но не работу на реальном телефоне. Восстанови изменённые параметры после исследования.

Если режим недоступен, выполни доступный веб-сценарий, пометь мобильную часть «не проверено» и укажи, какая среда нужна для проверки. Не делай вывод о сходстве платформ из одного десктопного экрана.

## Авторизация и секреты

В схеме `browser_fill`, проверенной 2026-10-04, есть `ref`, `text`, `tab`; ссылки на env/защищённое хранилище нет. Сохранение внешнего env-файла само по себе не подключает его к браузеру. Не передавай пароль обычным аргументом `text` и не используй `browser_eval` для чтения env, cookies, токенов или скрытого входа. Проверь актуальную схему на наличие документированного безопасного механизма; если его нет, пользователь авторизуется в исследовательской вкладке самостоятельно. После этого проверь видимое состояние сессии, не снимая экраны с заполненными данными входа.

При прямом разрешении пользователя на открытый `text` действует исключение из основного скилла: ввод в наблюдаемую форму Mashina.kg разрешён без повторного подтверждения. Оно не делает аргумент защищённым и не разрешает скрытый вход через внутренние API. До ввода должны существовать актуальные refs полей; после отправки проверяй фактическую авторизацию. Успешный ответ инструмента click/fill не доказывает изменение интерфейса.

## Если пользователь имеет в виду встроенный desktop BB Browser

MCP сервера `bb-browser` и CLI `bb browser` — разные интерфейсы. Не заявляй, что MCP управляет конкретным встроенным окном или использует его авторизацию, пока это не подтверждено.

Для явно выбранного пользователем встроенного браузера прочитай `bb guide browser`. Найди desktop через `bb browser instances --host <проверенный-host-id> --json`. Операциям вкладок и контроля нужны явные `--host`, `--instance`, `--generation`, `--thread` из актуального состояния. CLI предоставляет вкладки, capture и контроль; для взаимодействия со страницей требуется доступная интеграция автоматизации.

Не импортируй cookies, не создавай и не печатай connection credentials в рамках обычного исследования. Если подходящей интеграции нет, сообщи об этом конкретном ограничении; не считай команды контроля вкладок достаточными для исследования сценария.
