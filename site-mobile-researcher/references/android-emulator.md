# Работа с Android-приложением через эмулятор

Эта инструкция относится к нативному Android-приложению Mashina.kg. Установка и команды ниже проверены 2026-10-05 на Windows 11. iOS-приложение этим способом не проверяется: симулятор iOS на Windows недоступен.

## Что установлено

| Компонент | Значение |
|---|---|
| Android SDK | `C:/Users/ueabq/AppData/Local/Android/Sdk` (`cmdline-tools`, `platform-tools`, `emulator`) |
| JDK 17 (нужен только `sdkmanager`/`avdmanager`) | `C:/Program Files/Eclipse Adoptium/jdk-17.0.20.101-hotspot` |
| Образ | `system-images;android-35;google_apis_playstore;x86_64` — Android 15 с Google Play |
| AVD | `mashina_pixel7` — Pixel 7, 1080x2400, 420 dpi, 3 ГБ RAM, Play Store включён |
| Ускорение | WHPX, проверка: `emulator.exe -accel-check` |

Переменные `ANDROID_HOME`/`PATH` в системе не прописаны: вызывай инструменты по полному пути. Не обновляй SDK, не создавай новые AVD и не ставь дополнительные образы без запроса пользователя.

## Запуск и остановка

Команды даны для Bash (Git Bash). `MSYS_NO_PATHCONV=1` обязателен, иначе пути вида `/sdcard/...` искажаются.

```bash
SDK="$LOCALAPPDATA/Android/Sdk"; ADB="$SDK/platform-tools/adb.exe"; export MSYS_NO_PATHCONV=1

"$ADB" devices                      # сначала проверь, не запущен ли эмулятор уже
"$SDK/emulator/emulator.exe" -avd mashina_pixel7 -no-boot-anim   # запускать в фоне, процесс живёт до закрытия
"$ADB" wait-for-device
"$ADB" shell getprop sys.boot_completed   # ждать значение 1; холодный старт занимает около 40 секунд
"$ADB" emu kill                     # остановить эмулятор, когда он больше не нужен
```

Тёмный экран при `mCurrentFocus=null` обычно означает, что устройство уснуло: проверь `"$ADB" shell dumpsys power | grep mWakefulness=` и разбуди через `"$ADB" shell input keyevent KEYCODE_WAKEUP`. В AVD включены `svc power stayon true` и тайм-аут экрана 30 минут.

Если экран не реагирует на нажатия, а команды `input` зависают, проверь `"$ADB" shell dumpsys window | grep -E "mCurrentFocus|ANR"`. При `Application Not Responding: system` помогает холодная перезагрузка гостя: `"$ADB" reboot`, затем снова дождаться `sys.boot_completed=1`; данные и вход в Google сохраняются. Так было 2026-10-05 после запуска из снимка состояния при ~0,5 ГБ свободной памяти на ПК (эмулятор занимает около 4 ГБ). Вызовы `adb` оборачивай в `timeout`, чтобы зависший гость не блокировал ход.

Эмулятор открывает окно на рабочем столе пользователя. Если его запустил ты, останови его после исследования; эмулятор, запущенный пользователем, не трогай. Не используй `-wipe-data`: это стирает вход в Google и установленное приложение.

## Приложение

Приложение ставится из Google Play. Вход в Google-аккаунт и установку выполняет пользователь в окне эмулятора; не проси логин, пароль или код в чате и не вводи их через `input text`.

```bash
"$ADB" shell am start -a android.intent.action.VIEW -d "market://search?q=mashina.kg&c=apps"   # открыть поиск в Play
"$ADB" shell pm list packages | grep -i mashina        # найти фактическое имя пакета
"$ADB" shell dumpsys package <пакет> | grep versionName  # версия для отчёта
"$ADB" shell monkey -p <пакет> -c android.intent.category.LAUNCHER 1   # запустить приложение
```

На 2026-10-05 в AVD выполнен вход в Google и установлено приложение `com.espiru.mashinakg` версии 3.0.20 (в Play — «Mashina.kg - авто объявления», ESPIRU LLC). Пользователь сам вошёл в профиль Mashina.kg в приложении; наличие сессии не расширяет поручение, а экраны профиля снимай только без личных данных. Перед исследованием всё равно проверь наличие пакета, фактическую версию и видимое состояние авторизации. Системные диалоги разрешений (уведомления, геолокация, камера) относятся к настройкам пользователя: фиксируй их как шаг сценария и не выдавай разрешения без поручения.

Имя пакета не угадывай: бери из `pm list packages`. Если приложение не установлено или Play требует входа, верни блокер с точным видимым текстом. APK из сторонних источников не скачивай; файл, переданный пользователем, ставь через `adb install <путь>`.

## Чтение экрана и действия

```bash
"$ADB" exec-out screencap -p > OBS-01_android.png          # скриншот сразу в PNG-файл
"$ADB" exec-out uiautomator dump /dev/tty                    # XML-дерево экрана: text, resource-id, bounds
"$ADB" shell dumpsys window | grep mCurrentFocus             # текущее приложение и экран (activity)
"$ADB" shell input tap <x> <y>                               # нажатие
"$ADB" shell input swipe 540 1600 540 800 300                # прокрутка вверх на ~800 px
"$ADB" shell input text "toyota"                             # ввод в поле с фокусом; только латиница и цифры
"$ADB" shell input keyevent KEYCODE_BACK                     # также KEYCODE_HOME, KEYCODE_ENTER
```

- Дерево `uiautomator` — аналог snapshot в браузере. Координаты нажатия бери из атрибута `bounds="[x1,y1][x2,y2]"` нужного элемента (центр прямоугольника), а не оценивай по картинке. Координаты считаются в пикселях экрана 1080x2400; просмотренное изображение может быть уменьшено.
- После каждого действия получай новое дерево или скриншот: успешный `input tap` не доказывает, что экран изменился. Экраны на WebView, Compose или с анимацией могут отдавать неполное дерево — тогда опирайся на скриншот и отметь это.
- Кириллицу `input text` не вводит. Если сценарий требует русского текста, выбирай значения нажатиями по подсказкам и спискам либо зафиксируй ограничение.
- Не используй `adb shell` для чтения данных приложения, токенов, баз и настроек, `adb root`, `pm clear` и удаление приложения. Перехват трафика и подмена сертификатов не входят в исследование.

## Запись в отчёте

Указывай платформу «Android-приложение (эмулятор)», версию приложения, версию Android, модель AVD и размер экрана. Эмулятор подтверждает поведение приложения в этой версии и на этом образе, но не на реальном устройстве: push-уведомления, камера, геолокация, оплата, производительность и вход по SMS могут отличаться. Сравнение с мобильным вебом оформляй как сравнение разных платформ; общие правила скриншотов, OBS-ID, личных данных и границ действий из `SKILL.md` действуют без изменений.
