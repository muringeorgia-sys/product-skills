# Механики под план выручки

От метрики плана к гипотезам, что делать. Механика не даёт решение: она показывает, где в графе работ искать. Из всех подходящих обычно срабатывают 2–4.

## Вход

- Бизнес-задача словами PO: «добрать Промо в ноябре», «вернуть платящих продавцов».
- Нет числа цели — возьми план и прогноз категории из `04_outputs/final/po-dashboard/data.json` (`revenue.categories`, есть дата среза). Расходится с финотчётом — верен финотчёт.
- Нет данных ни там, ни у PO — пиши «нет данных». Числа не придумывай.

## Шаги

### 1. Проверить цель

- 3–5 раз «Зачем?» вверх: фича → конверсия → продажи → маржа → цель года. На каждом уровне — нет ли более прямого пути.
- Задача — уже решение («добавить функцию»)? Подними её на уровень метрики.
- Трек из `Skills-Results/mashina.kg/nmt-base/focus.json`: «Деньги сейчас» (локальный) или «Смена модели» (глобальный, решают PO и CEO).
- Что не должно ухудшиться — 1–2 метрики.
- Тип задачи по Замесину — по таблице «Метрика плана → задача» в `references/impact-rice.md`.

### 2. Текущее состояние

- Разрыв: факт или прогноз против плана категории, источник и дата.
- База NMT: сначала `Skills-Results/mashina.kg/nmt-base/SUMMARY.md`, детали — по id в `segments.json`, `jobs.json`, `values.json`, `risks.json`. Какие сегменты дают деньги категории, какие работы и проблемы у них есть, что Mashina делает сейчас.
- Роадмап и уже оценённые фичи: `S08_22.10-11.11/Оценка_Выручка-по-фичам-роадмапа_2026-10-23.md`. Не дублируй их как новые гипотезы — ссылайся.
- Нужны свежие цифры сверх этого — задача для `mashina-analyst`, не собирай сам.

### 3. Механики-кандидаты

- По типу задачи возьми механики из `references/mechanics.md`, таблица 1.
- Оставь 3–6, в которые веришь сильнее всего. У каждой — где искать в графе (id работ) и что неизвестно.
- Первый приоритет у Замесина: «починить проблемы» (6) и «работа, которую ищут, но никто не выполняет» (5).

### 4. Деньги в следующей работе — обязательно

Для каждой Core Job сегмента посмотри следующую работу в цепочке: кто на ней сейчас зарабатывает и можем ли мы. Для покупателя авто — кредит, лизинг, переоформление, страховка. Урок Замесина: деньги часто лежат в следующей работе, а не в выбранной. Итог — отдельная таблица в результате.

### 5. Гипотезы

- Формат: «сегмент × работа × механика → конкретное действие».
- Гипотеза засчитывается, только если Big Job сегмента выполняется лучше по его же критериям успеха.
- Антипроверка (из конспекта, проверять): не сделает ли то же крупный игрок для всей своей базы — банк, другая площадка.

### 6. RICE

- По `references/impact-rice.md`: R, I по шкале задачи, C по уровню доказанности, E в неделях команды.
- Для топа — ещё сом в месяц по методике `S08_22.10-11.11/Методика_Выручка-по-фичам-роадмапа_2026-10-23.md`: мин / база / макс.
- Фильтр юнит-экономики: если гипотеза в принципе не даёт маржу на платящего — убрать, даже красивую.
- Что теряем, выбирая топ, — одной строкой (opportunity cost).

### 7. Топ-3 и как проверить

- У каждой — рискованное допущение в позитивной форме: «частники платят N сом за …», а не «могут не заплатить».
- Самая дешёвая проверка: данные (`mashina-analyst`), интервью (`ajtbd-interview-guide`), UX-тест прототипа (`ux-test`), решенческое интервью или MVP. Порядок цены: данные → эксперт 30 минут → интервью → UX-тест → MVP.
- Метрика проверки с колонками «Данные сейчас» и «Что нужно для сбора».
