# Cases and delivery

Use this route for cases, MVPs, solution choice, feature launch, and prioritization.

## Minimum clarifications

Ask only what the case does not provide:

1. Which business goal and metric must change?
2. Which segment or scenario is in focus?
3. What is already known from data, research, or past attempts?
4. Which time, risk, resource, or technology constraints apply?
5. Which criterion will determine the decision?

## Decision frame

1. Fix the goal and working assumptions.
2. Segment the audience or scenarios so that priority is evidence-based.
3. Gather or request data and research that test the problem cause.
4. Form two or three solution options and compare impact, confidence, and effort.
5. Choose one minimum solution instead of doing everything at once.
6. Validate it with a prototype, pilot, A/B test, or cohort comparison; define rollout, metric, and risk.

## Case-type diagnostics

- **New direction / MVP:** start with business goal and segment, then investigate the problem.
- **Metric decline:** first check data, cohorts, and segments; do not start with solutions.
- **Choice between two options:** first define value, criteria, comparison evidence, and cost of error. Do not claim an option is better before the criteria exist.
- **Delivery:** add owner, dependencies, definition of done, rollout, and rollback.
