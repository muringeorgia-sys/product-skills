# Статус эпиков

## Выборка

| Запрос PO | Эпики |
|---|---|
| «статус по эпикам», без уточнения | Открытые эпики Mashina.kg ближайших двух релизов + эпики в Разработке без релиза |
| «что с эпиком X» | Один эпик |
| «что к релизу ДД.ММ» | `fixVersion = "<Продукт> ДД/ММ/ГГГГ"` по каждому продукту |
| «по House / Bazar / финтеху» | Фильтр по Продукту или `labels = Fintech` |

## Что собрать по эпику

- Эпик: ключ, тема, статус, исполнитель, fixVersion, метки, RICE, ссылка на требования, ссылка на дизайн, дата последнего перехода.
- Дочерние: `cf[10108] = <ключ>` в MASH, QA, DESIGN + подзадачи этих задач (`parent in (...)`). По каждой: ключ, тип, статус, исполнитель, версия, дней в статусе.

## Агрегат задач MASH → ожидаемый статус эпика

| Задачи MASH эпика | Ожидаемый статус эпика |
|---|---|
| Есть в Backlog, Selected for Development, Holding, Kickback, Сделать | Бэклог разработки |
| Нет в бэклоге, есть в В работе, Review, Ready to test, In testing | Разработка |
| Все открытые в Ready to release | Готово к выпуску |
| Все Готово | Выпущено |

Расхождение с фактическим статусом — пометка «⚠ статус» и проверка правил 34/35.

## Риск по релизу

| Риск | Условие |
|---|---|
| Высокий | До релиза ≤ 7 дней, эпик ещё в Discovery или есть задачи MASH в бэклоге |
| Средний | До релиза ≤ 7 дней, задачи в Разработке; или карточка застряла (порог в `checks.md`, F6) |
| Низкий | Всё в Готово к выпуску / Готово или до релиза > 7 дней по плану |

## Формат отчёта

1. Итог: 3–5 строк — сколько эпиков, сколько в риске, что блокирует.
2. Таблица эпиков, по одной строке:

| Эпик | Статус | Релиз | MASH | QA | DESIGN | Риск |
|---|---|---|---|---|---|---|
| PRODUCT-298<br>Проверка по VIN | Разработка | 22.10 | 3 из 5 готово<br>1 Kickback | готово | готово | Средний |

   Ячейки короткие, списки через `<br>`.
3. Блокеры: эпик · задача · статус · дней · кто.
4. Нарушения процесса, найденные по ходу (ссылка на код проверки из `checks.md`).
5. Что не проверено и почему.

Без запроса PO ничего в Jira не меняешь.
