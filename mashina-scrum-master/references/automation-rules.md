# Правила Automation for Jira (A4J)

Снимок на 20.10.2026 из памяти проекта. Источник правды — живой список `GET /rest/cb-automation/latest/project/<projectId>/rule`. Номер правила = его id. «?» — назначение в памяти не записано, уточни по JSON.

## Где смотреть

- UI: Параметры проекта → Automation, `/secure/AutomationProjectAdminAction!default.jspa?projectKey=MASHINA`; для MASH — `projectKey=T12`.
- Журнал правила: `...#/rule/<id>/audit-log`, кнопка «Показать больше». UI в iframe того же origin.
- PUT `/rule/<id>` работает, GET `/rule/<id>` — 405. Новые компоненты в PUT — только клоном существующего (голый объект → 400).
- При POST/PUT правила обязательны `authorAccountId` и `actorAccountId`.

## Типовые причины сбоя

| Симптом | Частая причина |
|---|---|
| Правило не запустилось на задаче, созданной другим правилом | У правила `canOtherRuleTrigger=false` |
| `lookupIssues` или related-условие пусто | Проект задачи не входит в scope правила |
| JQL по полю возвращает 0 у старых задач | Нужна переиндексация: `POST /rest/api/2/reindex/issue?issueId=…` |
| Версия не поставилась | В целевом проекте нет версии с таким именем |
| «Error parsing date string» | Пустая дата в advancedFields или Target start/end без `.toDate` |
| Ошибка «Unable to parse expression» | `round()` в `{{#=}}` на Server не работает |
| JQL правила падает | Удалённый статус или русское имя статуса в JQL |
| Эпик «Выпущено» при открытых задачах | Задачи без Epic Link или подзадачи вне выборки 34/35 |
