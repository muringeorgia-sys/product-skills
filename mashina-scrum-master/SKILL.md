# Scrum-мастер Mashina.kg

Сначала `lore.md`, затем этот файл, затем `references/jira-map.md`.

## Справочники

| Файл | Когда открывать |
|---|---|
| `references/jira-map.md` | Всегда: проекты, статусы, поля, доски, люди, доступ |
| `references/labels.md` | Режим «Метки» и общая проверка |
| `references/automation-rules.md` | Режим «Правила» и общая проверка |
| `references/checks.md` | Режим «Проверка»: JQL-инварианты |
| `references/epic-status.md` | Режим «Статус эпиков»: формат отчёта |

## Режимы

Определи режим по запросу. Не ясно — один вопрос AskUserQuestion, первым вариант «Полная проверка».

| Режим | Запрос | Результат |
|---|---|---|
| Метки | «проставь / проверь метки» | Список правок меток → «да» → запись → сверка |
| Правила | «проверь автоматизацию», «почему не сработало» | Таблица правил: работает / сбой / причина / правка |
| Проверка | «проверь Jira», «гигиена», «сверь с Confluence» | Отчёт нарушений по `checks.md` |
| Статус эпиков | «статус по эпикам», «что с эпиком X», «что к релизу» | Отчёт по `epic-status.md` |
| Полная проверка | «посмотри всё», без уточнения | Проверка + Метки (предложения) + Правила (сбои) |

## Порядок работы

1. **Доступ.** Один `ToolSearch` на инструменты Comet (список — `jira-map.md`, раздел «Доступ»). `list_connected_browsers` → `select_browser` на Comet. Новая вкладка на `https://jira.mashina.kg/`. Не залогинен — скажи PO и остановись.
2. **Срез.** Данные бери REST-запросами `fetch` из вкладки, не кликами. Пагинация `startAt/maxResults=100`. Большие ответы клади в `<pre>` на странице Jira и читай `get_page_text`. Сырые выгрузки — в `tmp/scrum-master/YYYY-MM-DD/` проекта.
3. **Сверка с памятью.** Прочитай последние пункты `jira-mashina-setup.md` в памяти проекта: что менялось после даты справочников. Расхождение — верь живому REST, отметь в отчёте одной строкой.
4. **Работа по режиму** — шаги ниже.
5. **Отчёт** `.md` в папку текущего спринта: `S0N_ДД.ММ-ДД.ММ/Скрам_<Тема>_YYYY-MM-DD.md`. Папку спринта выбирай по сегодняшней дате из имён папок в корне проекта. Структура: итог в 3–5 строк → таблица нарушений или статуса → предложенные правки → что не проверено и почему.
6. **Вики.** Новый отчёт — строка в `_ВИКИ/index.md` и запись в `_ВИКИ/log.md` по формату соседних строк.
7. **Ответ.** Ссылка на отчёт и 1–2 строки. Если есть правки на согласование — вопрос AskUserQuestion: «Применить все» (рекомендуется) / «Выборочно» / «Не применять».

## Режим «Метки»

1. Выборка по `labels.md`, раздел «Охват». Для каждой карточки: тема, описание, Продукт, текущие метки, ссылка на требования (10209). Требования в Confluence или в `.md` проекта читай, если по теме категория неочевидна.
2. Категория выручки по правилам `labels.md`. Нет прямой связи с выручкой — функциональная метка. Не уверен — в таблицу «Нужно решение PO» с 2 вариантами, не угадывай.
3. Таблица правок: Ключ · Тема · Сейчас · Добавить · Основание (одна фраза).
4. «Да» PO → запись. Перед каждой записью перечитай `labels` задачи; пиши `update: {labels: [{add: "..."}]}`, не перезаписывай массив. По 3–4 записи на вызов `javascript_tool`.
5. Сверка: повторная выборка, все добавленные метки на месте, старые сохранены. Протокол — `tmp/scrum-master/YYYY-MM-DD/labels-*.json`.

## Режим «Правила»

1. Список правил: `GET /rest/cb-automation/latest/project/<projectId>/rule` для 10001, 10002, 10102, DESIGN, 10100. Одно правило по `/rule/{id}` даёт 405 — бери из списка. Сохрани JSON в `tmp/scrum-master/`.
2. Сравни с `automation-rules.md`: включено/выключено, триггер, scope, JQL. Изменения против справочника — в отчёт.
3. Для каждого включённого правила — инвариант из `checks.md`. Нарушение = кандидат на сбой.
4. Для кандидата открой журнал в UI: `/secure/AutomationProjectAdminAction!default.jspa?projectKey=<KEY>#/rule/<id>/audit-log` (iframe того же origin, читай через `document.querySelector('iframe').contentDocument`, «Показать больше»). Ошибка, «нет действий» или нет запуска.
5. Причину ищи по типовым сбоям `automation-rules.md`, раздел «Типовые причины».
6. Таблица: Правило · Что делает · Статус (работает / сбой / не проверено) · Доказательство (ключ задачи, запись журнала) · Причина · Правка.
7. Правки правил — только по «да» на каждое правило (см. `lore.md`, «Права на запись»). E2E-тест — только по отдельному «да».

## Режим «Проверка»

Прогони все JQL-инварианты из `checks.md`. Для каждого: число нарушений, до 10 ключей, вероятная причина, правка. Сверка с Confluence — раздел «Jira ↔ Confluence» там же. Пустые проверки покажи одной строкой «ок», без таблиц.

## Режим «Статус эпиков»

Выборка, сбор задач и формат — `epic-status.md`. Без запроса PO не меняешь ничего.

## Если что-то сломалось

- `javascript_tool` упал по таймауту 45 с — сначала проверь состояние на сервере, потом повторяй, иначе дубли.
- Вывод режется около 1000 символов; строки с URL и `?`/`&` блокируются — выводи ключи и числа, ссылки собирай сам.
- 401/403, просьба WebSudo — остановись, скажи PO, что ввести.
- Классификатор блокирует запись (Modify Shared Resources) — не обходи, запроси у PO явное «да» на конкретное действие.
