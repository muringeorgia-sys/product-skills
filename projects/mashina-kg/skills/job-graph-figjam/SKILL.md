# Граф работ в FigJam

Строит одну секцию FigJam на сегмент. Данные — JSON, сборка — готовый скрипт для `use_figma`.

## Структура доски (образец)

| Зона | Что | Вид |
|---|---|---|
| Верх слева | Big Job сегмента | белая карточка, заголовок 40 Bold,<br>когда / хочу / чтобы 24 |
| Верх рядом | «Как читать» и источники | белая карточка, 18 |
| Верх справа | Соседние Big Jobs<br>(эмоции, другие мотивы) | белые карточки, красная пунктирная<br>стрелка к работе, которую они двигают |
| Ряд шевронов | Этапы пути во времени,<br>«Этап → срок» | CHEVRON 168 px, цвета от красного<br>к зелёному: #C91D00 → #DA5606 →<br>#E68600 → #C9A000 → #85B814 |
| Под этапами (опц.) | Подэтапы: плохое / хорошее решение | CHEVRON 86 px, #818181 / #3D7D5B |
| Полоса 0 | Работа этапа (уровень этапа) | белая полоса во всю ширину |
| Полосы 1–3 | Работы ниже уровнем | белые полосы |
| Рамка | Повторяющаяся группа работ | пунктир #F24822 + плашка<br>«Повторено N раз» |

**Карточка работы** — три блока ширины 700 px один под другим:

| Блок | Текст | Цвет |
|---|---|---|
| Работа | заголовок 24 Bold;<br>**когда** … **хочу** … **чтобы** … (16);<br>важность, частота, длительность;<br>**Mashina сейчас:** … | #FFFFFF, рамка #CCCCCC |
| Решения | «Решения:» + список: чем решают сегодня | #FCD19C, рамка #CAA77D |
| Проблемы | «Проблемы:» + список с источником;<br>эмоции с оценкой N/10, если есть интервью | #F5A59E, рамка #C4847F |

**Связи** (чёрные #1E1E1E, 3 px, ELBOWED, стрелка ARROW_LINES):
- `chain` — следующая работа в цепочке: правый край → левый край.
- `down` — работа ниже уровнем: от «Проблем» родителя вниз к работе. Так читается «решение не сработало — появилась новая работа».
- `back` — возврат («Не успех», «Не помогает»): верх → верх, с подписью.

Фон секции #FFF2DF. Шрифт Inter Medium и Bold.

## Правила содержания

- Работы формулирует канон NMT: когда (ситуация) / хочу (ожидаемый результат) / чтобы (работа уровнем выше). Без «прогресса» и без нескольких глаголов в одной работе.
- Этапы — это шаги пути сегмента во времени, а не экраны продукта.
- У каждой проблемы источник в скобках: «11 из 100 отзывов», «Redash», «гипотеза».
- Нет интервью — важность, частота, длительность, эмоции пишутся «нет данных». Не выдумывать.
- Строка «Mashina сейчас» — делаем / частично / в работе (эпик, релиз) / не делаем / статус не проверен.
- Источники в тексте графа не писать: никаких «(ОИ: …)», «(гипотеза)», «(N из M отзывов)», «(Redash)». Текст карточек — только суть.
- Пробелы по просьбе PO можно дополнить из открытых источников; список источников держать в сопроводительном .md, не на доске.
- Граф без интервью получает одну общую боковую плашку (поле `disclaimer`): «Собрано из интернета и придумано, без общения с клиентами» + 2–3 строки. Плашка справа от графа: жёлтая, толстая красная рамка, крупный шрифт, не перекрывает работы. Без списка источников и легенды меток.

## Как собрать

1. Заполнить JSON по схеме ниже. Образцы — `Skills-Results/mashina.kg/nmt-chat/job-graph-figjam/*.json`.
2. Проверить и склеить код:
   `node .claude/skills/job-graph-figjam/scripts/compose.mjs <data.json> tmp/<name>.code.js`
   Скрипт проверяет связи и лимит 50 000 символов `use_figma`.
3. Загрузить правила Figma: `skill://figma/figma-use/SKILL.md` и `skill://figma/figma-use-figjam/SKILL.md`.
4. Файл FigJam: `create_new_file` (editorType `figjam`, план с правом создания; в Mashina team у PO роль гостя — файл создаётся в личной команде), затем `create_session`.
5. Вызвать `use_figma` с кодом из шага 2, `skillNames: resource:figma-use,resource:figma-use-figjam`. Несколько досок в одном вызове: обернуть тело `build-board.js` в `async function build(DATA){…}` и задать каждой `x`, `y` (шаг по y ≈ высота + 1 400).
6. Проверить `get_screenshot` секции; текст карточки — скриншотом группы блоков через `node.screenshot()`.

## Схема JSON

```json
{
  "title": "Граф работ: <сегмент>",
  "x": 0, "y": 0,
  "note": "Как читать … Источник …",
  "bigJob": { "title": "", "when": "", "want": "", "so": "" },
  "sideJobs": [ { "id": "", "col": 2, "title": "", "when": "", "want": "", "so": "", "targets": ["<job id>"] } ],
  "stages": [ { "title": "Этап → срок", "from": 0, "to": 1 } ],
  "subStages": [ { "title": "", "from": 0, "to": 1, "tone": "bad|good" } ],
  "jobs": [ { "id": "", "col": 0, "row": 0, "title": "", "when": "", "want": "", "so": "",
              "metrics": "Важность, частота, длительность: …", "mashina": "",
              "solutions": [""], "problems": [""] } ],
  "edges": [ { "from": "", "to": "", "kind": "chain|down|back", "label": "" } ],
  "repeats": [ { "label": "Повторено N раз", "cols": [2, 4], "rows": [1, 2] } ],
  "disclaimer": "Граф собран из открытых источников в интернете и гипотез команды. С клиентами не общались …"
}
```

`col` — колонка 784 px (карточка 700 + зазор). `row` — полоса уровня. Шеврон этапа покрывает колонки `from…to`. `x`, `y` не заданы — секция встаёт справа от последней.

## Ограничения

- Высота блоков считается по длине текста примерно; слишком длинный пункт лучше разбить.
- Связи `back` через несколько колонок идут над полосой — давать им короткую подпись.
- Дерево не обязательно: одна работа может быть целью нескольких `down` и `sideJobs`.
