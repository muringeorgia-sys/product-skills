# Флоу создания эскиза приложения Mashina.kg

Обновлён по указанию пользователя 2026-10-06: смотреть только Android-эмулятор, затем создавать дизайн. Существующий интерфейс переносится скриншотами; новые и изменённые элементы — отдельными редактируемыми слоями. Этот режим заменяет прежний флоу с MAD. Новая версия пока не проверена созданием макета.

## 1. Согласовать результат

Прочитай требования целиком, включая критерии приёмки. Уточни только отсутствующие решения: платформа, объём экранов и состояний, место записи, аккаунт и команда. Не спрашивай повторно разрешение на скриншоты: пользователь уже выбрал этот режим. Если явно нужна полная редактируемость, применяй выбранный пользователем режим.

Источник текущего интерфейса — только установленное приложение в Android-эмуляторе. Не открывай MAD, не вызывай его коннектор, не читай прежние выгрузки и не используй ранее полученные оттуда компоненты, иконки, фотографии или значения. Figma используется для создания результата и чтения его целевого участка при доработках.

Не считай мобильный веб референсом приложения. Не переноси объём, аккаунт или размеры прошлого эскиза на новую задачу. При тяжёлой работе согласуй оценку по правилам среды.

## 2. Снять нужные экраны

- Прочитай site-mobile-researcher и references/android-emulator.md. Проверь SDK, AVD, пакет, версию приложения и состояние устройства; используй существующий эмулятор. Установки требуют согласования.
- Открывай только путь, нужный для выбранного сценария. Координаты бери из актуального дерева UI. После действия проверяй новый экран; при ошибке dump не используй старый XML как свежий.
- Сними и просмотри нужные экраны. Для длинной страницы сними необходимые участки, сохраняя порядок и перекрытие для точной обрезки. Не выгружай полное дерево UI в контекст, если достаточно целевых элементов.
- Не переноси в итог телефоны, лицевые счета, секреты и другие личные данные. Скриншот с такими данными подготовь к использованию без них до загрузки в Figma. Исследование не разрешает покупку, публикацию или изменение аккаунта.
- Если эмулятор отключился, сделай ограниченную попытку восстановления по инструкции. Если нужный экран недоступен, отметь пробел; не переходи к MAD. Продолжай независимые части, а блокирующие решения уточни.
- После получения достаточного референса переходи к сборке без дополнительного исследования дизайна. Останови эмулятор, если запустил его сам.

## 3. Собрать макет в Figma

Проверь инструменты записи и аккаунт через whoami. Перед записью загрузи обязательные figma-use и figma-generate-design, перед созданием файла — figma-create-new-file. Объяви место и объём записи. Сохраняй ключ файла и ID созданных узлов для доработок без дублей.

- Переноси неизменённые части как image fills из скриншотов эмулятора: весь неизменённый экран или отдельные обрезанные блоки. Не пересоздавай внутри них тексты, кнопки, карточки, иконки и фотографии.
- Выдели области изменений по PRD. Исключи заменяемые элементы из фрагментов или полностью закрой их фоном и новыми слоями. Не оставляй старые тексты, цены и кнопки видимыми рядом с заменой. При увеличении блока сдвигай нижние фрагменты, чтобы они не перекрывались.
- Сохраняй масштаб и пропорции снимков, выравнивай обрезки без повторения строк и швов. Учитывай статус-бар и нижнюю навигацию, чтобы они не дублировались. Для длинной страницы переноси весь согласованный контент.
- Новые и изменённые элементы создавай редактируемыми: тексты, отдельные элементы управления, Auto Layout для связанных блоков. Стиль бери визуально из эмулятора; не строй библиотеку компонентов ради эскиза.
- Используй доступные шрифты. Проверь переносы, высоту текста и символ сома. После resize и добавления в Auto Layout проверь textAutoResize и реальную высоту: ранее текст мог сохранять высоту 1 px. При изменении высоты пересчитай положение нижней панели.
- Поведение и точные новые формулировки бери из PRD. Цены конкретного объявления не считай базовыми; неподтверждённые значения не выдумывай. Размеры, выбранный тариф и период из примера не становятся значениями по умолчанию.
- Допущения, демонстрационные данные и ограничения указывай в сопроводительной заметке, вне пользовательского интерфейса. Названия слоёв должны различать скриншоты и новые элементы.
- При ошибке use_figma следуй safeToRetryWithoutCanvasRead. Перед повтором, требующим чтения холста, проверь уже созданные узлы; не повторяй всю сборку вслепую.

## 4. Проверить и передать

Просмотри рендер каждого экрана: качество и масштаб снимков, стыки фрагментов, отсутствие повторов и видимых заменяемых элементов, читаемость новых текстов, наложения и границы контейнеров. После исправления проверяй только затронутый экран.

Структурно проверь image fills скриншотов и отдельные тексты/элементы новых блоков. Не проверяй и не обещай редактируемость содержимого скриншотов. Сопоставь согласованные экраны и состояния с требованиями. Если заказан кликабельный прототип, настрой доступные переходы отдельно; статичные экраны не называй прототипом.

Сохрани ссылку, итоговые превью, краткое покрытие требований и ограничения по правилам проекта. Обнови лог и каталог вики при создании документа; AGENT_STATUS — если проект его использует.

В финале укажи ссылку, экраны, выполненные проверки и пробелы. Явно напиши: существующие части — скриншоты, новые и изменённые элементы — редактируемые слои. Не называй весь макет полностью редактируемым.
