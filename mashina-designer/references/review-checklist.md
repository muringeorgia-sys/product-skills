# Самопроверка прототипа перед сдачей

Проходи по снимкам из `shoot.cjs` и по живому файлу. Пункт не проверен — так и пиши в ответе.

## 1. Дизайн-система

- [ ] Цвета, отступы, радиусы, тени, шрифты — только `var(--…)` из `tokens.css`. В сборке нет предупреждений о сырых цветах.
- [ ] Компоненты взяты из `kit.html`: кнопки, поля, чипы, табы, ячейки, карточки, бейджи, алерты, тосты.
- [ ] Варианты по назначению: одна главная кнопка на экран или блок, остальные — вторичные.
- [ ] Типографика по ролям из `design-system.md`, без «своих» размеров.
- [ ] Шаг сетки 4/8: отступы кратны базе DS.
- [ ] Всё, чего нет в DS, помечено `data-ds="НЕТ В DS: …"` и перечислено в `handoff.md`.
- [ ] Нет логотипов, цветов и шрифтов конкурентов.
- [ ] Нет «старого» стиля живого сайта: #0f67ff, радиусы 12–16 у кнопок, тёмные блоки — если их нет в DS.
- [ ] Иконки — только из `design-system/icons/`; недостающие заменены текстом и помечены «НЕТ В DS».

## 2. Раскладка

- [ ] Web 1440: контейнер, сетка и шапка — как на текущем сайте (`references/site-ui.md`), если PRD их не меняет.
- [ ] Mobile 390 — своя раскладка: одна колонка, главное действие в зоне большого пальца, длинные выборы — в шторке.
- [ ] 360 px: текст не обрезан, кнопки не съехали, цены не переносятся по цифрам.
- [ ] Первый экран показывает то, что PRD называет главным: заголовок, ключевое действие, главный блок.
- [ ] Порядок блоков — как в PRD или `.design.html`.
- [ ] Нет обрезанного текста, наездов, пустых дыр, горизонтального скролла на mobile.

## 3. Состояния и поведение

- [ ] У каждого применимого состояния есть способ его увидеть:
  - гость и вход;
  - роль: покупатель, частный продавец, дилер;
  - пусто;
  - загрузка;
  - ошибка сети или сервера;
  - длинные значения;
  - нет фото;
  - ноль результатов;
  - недоступная кнопка.
- [ ] Каждый CTA ведёт на экран, в окно, к тосту или к заглушке. Нет «мёртвых» кнопок.
- [ ] «Назад» и закрытие окон работают, Esc закрывает окно.
- [ ] Формы: обязательные поля, текст ошибки у поля, загрузка на кнопке при отправке. Обязательное согласие — кнопка отправки неактивна до отметки, как в калькуляторе сайта.
- [ ] Платное действие показывает цену до нажатия. Нет заранее включённых платных опций.
- [ ] Правила, которых не видно глазами, записаны в `data-note`.

## 4. Тексты и данные

- [ ] Тексты из PRD — дословно, с теми же подстановками.
- [ ] Свои тексты отмечены в `handoff.md` как «текст дизайнера».
- [ ] Нет lorem ipsum, TODO, «Текст кнопки».
- [ ] Числа: `2 186 250 ⃀`, `25 000 $` (в приложении `$25 000`), бонусы `1 434 Б`. Даты `16.10.2026`. Телефоны `+996 XXX XXX XXX`.
- [ ] Данные карточек правдоподобны для рынка КР: марки, годы, цены, города.
- [ ] Цены услуг, лимиты, сроки — только из PRD.
- [ ] Нет реальных персональных данных и внутренних цифр.

## 5. Доступность (WCAG 2.2 AA)

- [ ] Контраст текста ≥ 4,5:1, крупного текста и элементов интерфейса ≥ 3:1.
- [ ] Кликабельная зона ≥ 44×44 на mobile, ≥ 24×24 на web.
- [ ] Видимый фокус у полей и кнопок.
- [ ] У полей есть подписи, не только placeholder.
- [ ] Статус передаётся не только цветом: есть текст или иконка.

## 6. Аналитика и приёмка

- [ ] Каждое событие раздела 5 PRD висит на своём элементе или экране, параметры совпадают.
- [ ] В журнале «События» прохождение основного пути даёт ожидаемую последовательность.
- [ ] Каждый визуальный и поведенческий критерий раздела 6 можно показать в прототипе.

## 7. Файлы

- [ ] Сборка без ОШИБОК, `report.json` без ошибок JS и разметки.
- [ ] Файл открывается без интернета, весит меньше 2 МБ.
- [ ] Файл не тянет ничего с диска: скриншоты, картинки и шрифты встроены как `data:`; нет относительных ссылок на jpg/png/md, нет `http(s)`, CDN, `file:///`. Ссылки на скриншоты открывают их крупно внутри файла, не по пути. Проверка: файл открыт в headless Edge со свежим профилем, ошибок в консоли нет. Скриншоты делают файл тяжелее 2 МБ — допустимо, если без них нельзя.
- [ ] Web и mobile ссылаются друг на друга.
- [ ] В `handoff.md` есть экраны, переходы, «Нет в DS», допущения.
