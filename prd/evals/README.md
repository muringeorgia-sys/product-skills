# Эталонные прогоны скилла prd

Когда: после правки `prd`, `references/*` или агентов `prd-*`. Цель — правка не сломала то, что работало.

## Состав

- `cases.json` — 3 кейса из реальных брифов с решениями PO: `must` (обязано быть), `must_not` (не должно быть), `judge` (смысловые утверждения для судьи). Общие проверки — в `common`.
- `check_eval.mjs` — автопроверки: `prd_tools.js check`, `must`, `must_not`. Пишет `result.md` с таблицей для судьи.
- `runs.md` — история прогонов.

## Прогон (делает агент)

1. Папка `tmp/eval_prd_<ГГГГ-ММ-ДД>/`. Для каждого кейса — копия brief в `<id>_материалы/brief.md`, строки «Папка материалов» и «PRD» указывают в папку прогона, PRD — `<id>.md`.
2. `prd-core-pm-lite` по каждому кейсу (параллельно, в фоне): проход PRD «без концепции», без схем, не читать готовый PRD фичи, не писать вне папки прогона, не открывать браузер и прод (прогон проверяет текст, не прод).
3. `node ~/.claude/skills/prd/evals/check_eval.mjs tmp/eval_prd_<дата>`.
4. Судья — субагент `general-purpose`, model sonnet: заполняет таблицу «Для судьи» в `result.md` (PASS / FAIL + цитата).
5. Строка в `runs.md`. Хуже прошлого прогона — показать PO, что упало, и не считать правку готовой.

Дешёвый вариант: 1 кейс вместо 3. Калибровка проверок: `node check_eval.mjs --reference` — принятые PRD должны проходить без ошибок.

## Добавить кейс

Бриф с решениями PO + принятый PRD. `must` — короткие ключевые слова решений PO (регулярные выражения без учёта регистра), смысл — в `judge`. После добавления — `--reference`.
