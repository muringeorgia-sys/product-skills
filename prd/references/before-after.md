# Сравнение «Сейчас в проде / Будет»

Решение PO от 10.11.2026: в каждом PRD, Lite и Full, рядом с `<Фича>.md` лежит `<Фича>.before-after.html`. По нему за минуту видно, что меняется: слева прод сейчас, справа как будет. Автор - Product Designer. Файл публикуется в Confluence вместе с PRD (`publish.md`, «HTML-вложения»).

Образец после доработки 12.11.2026: `S05_10.09-23.09/Срок-жизни-объявления.before-after.html` и его `before_after.json` в папке материалов проекта Mashina.kg.

## Что внутри

Порядок на странице задаёт скрипт.

| Часть | Когда | Содержимое |
|---|---|---|
| Сводка | Всегда | Таблица «№ - Что - Сейчас в проде - Будет - Тип - PRD», 3-10 строк. Строка ведёт к своему экрану |
| Не показано | Есть изменения без экрана в сравнении | Таблица «Меняется, но в сравнении не показано»: пуши, логика, состояния без кадра, роли без изменений |
| Экраны | Фича меняет или добавляет экран | Раздел на экран: 2-4 пункта «что меняется», переключатель состояний, пара «сейчас - будет» с номерами правок на кадре, список правок. На desktop у каждой правки фрагмент кадра в натуральном размере: «сейчас → будет» |
| Процесс | Фича меняет шаги, статусы, правила без экрана | Схема или список шагов «сейчас» и «будет» картинками |
| Прототип | Больше одного нового или изменённого экрана | Кликабельные экраны «будет», mobile и desktop, рядом список «Куда можно нажать» со всеми переходами экрана. Стоит после экранов, в шапке кнопка «▶ Прототип» |

Фича без интерфейса (лимиты, логика, админка без макета): сводка обязательна, экранов нет, процесс - если есть схема в разделе 4. Файл всё равно создаётся.

В браузере: сворачиваемая шапка (решение PO от 11.11.2026), переключатель Desktop / Mobile, режимы «Рядом» и «Переключать» (один кадр на всю ширину, пробел меняет «сейчас» и «будет»), выключатель «Пометки правок», синхронная прокрутка пары, клик по кадру - крупно вместе с пометками, клик по строке правки показывает её место на кадре, под строкой правки на desktop - фрагмент кадра в натуральном размере (рисуется из встроенного кадра, файл не растёт). Прототип (замечание PO от 12.11.2026): экран прототипа целиком помещается в окно, колесо над ним листает только сам экран и не уводит страницу, кнопка «На весь экран» (Esc закрывает), зоны подсвечиваются при наведении, список «Куда можно нажать» дублирует все зоны текущего экрана кнопками. Всё делает скрипт, руками HTML не пишешь.

## Как страница должна читаться

Решение PO от 12.11.2026: сравнение понятно без чтения PRD и без поиска глазами. Проверяй себя по этим пунктам до сдачи.

1. **Цвет - только у правок.** Экраны «будет» и дорисованное «сейчас» остаются серыми, средней детализации. Зелёный - новое, синий - изменено, красный - убрано: этими цветами страница сама красит пометки, плашки и номера. На самих экранах цвет не добавляешь.
2. **Кадры чистые.** В сравнение и прототип экран идёт без пометок чертежа: без пунктирных рамок, ярлыков «новый» и «изменён», ID блоков и линии первого экрана (рендер с `--no-notes`). Правку показывает только цветная пометка страницы, а прототип выглядит как продукт. Без пометок экран должен выглядеть законченно: карточке - свой фон или рамка.
3. **Номер правки стоит на кадре и в списке.** У каждой правки одна строка в `changes` и пометка на кадре: рамка и номер. Номер - порядок строки в `changes` этого состояния. Читатель видит номер на кадре и находит тот же номер под кадром.
4. **Одна правка - одна вещь.** Не «изменён блок B1», а что стало другим: текст, кнопка, цена, поведение. Два изменения в одном блоке - две строки и две пометки на разных элементах. Пометка стоит на самом элементе: по ней страница вырезает фрагмент «крупно», и по большому блоку вместо кнопки он выйдет мелким.
5. **Изменённое видно с двух сторон.** У правки типа `changed` пометка стоит и на «сейчас», и на «будет»: в списке правок получается пара фрагментов «сейчас → будет» в натуральном размере. У `new` - только «будет», у `removed` - только «сейчас».
6. **Блоков без номера нет.** Каждый блок, который в HTML экрана помечен «новый» или «изменён», имеет строку в `changes` этого состояния и `data-chg`. Блок повторяется в другом состоянии - повтори строку и там.
7. **Экран - один раздел, состояния - переключателем.** Варианты одного экрана (вкладки, дни, «не хватает денег», окно поверх экрана) - это `states` одного экрана, а не отдельные разделы. Отдельный раздел - только другой экран. Разделов обычно 3-7.
8. **Главное - первым.** Первый раздел и первое состояние в нём - с главной правкой фичи. Порядок строк сводки тот же, что порядок разделов.
9. **Над парой - что меняется для пользователя.** `points`: 2-4 коротких предложения простыми словами, с текстами кнопок в кавычках. Без ID блоков, номеров пунктов и слов «блок B2».
10. **Сводка - про изменения, не про блоки.** Строка: что - как сейчас - как будет, тип, пункты PRD и критерии (`ref`), ссылка на экран (`screen`). ID блоков в сводке нет. Экрана на проде нет - в «Сейчас» пиши «Такого экрана нет».
11. **Что не показано - названо.** Изменения без кадра (пуши и SMS, фоновые правила, состояния, которые не рисовал, роли без изменений) перечисли в `outside` со ссылкой на пункт PRD. Читатель не должен гадать, забыто это или не меняется.
12. **Подстановки - в фигурных скобках:** `{date}`, `{цена публикации}`. Страница выделяет их сама. Цен и дат, которых нет в PRD, не придумываешь.
13. **В прототипе видно, куда нажать.** Подпись зоны (`label`) попадает в список «Куда можно нажать» рядом с экраном: пиши её как действие пользователя («Активировать», «Вкладка «Активные»»), а ветку по условию - с условием («Если не хватает денег»). Зон без подписи нет.

## Правила содержания

- **Сейчас** - только то, что видно на проде `mashina.kg` в день сборки: скриншоты и тексты дословно. Заявки на автофинансирование и лизинг - preprod. Не видел - не пишешь; это допущение в ответ оркестратору.
- **Состояния нет на проде или в тестовом аккаунте** (решение PO от 12.11.2026): нет активных объявлений, окно не снималось, экран за оплатой, пустой баланс. Не подставляй слева чужой скриншот с подписью «рисуется по PRD» и не останавливай сборку. Дорисуй «сейчас» сам как пример: экран средней детализации, раскладка и стиль - по соседним скриншотам прода, тексты прода дословно, где они известны (PRD, Confluence, сайт). HTML в `evidence/now/`, PNG в `evidence/now_<S>_<desktop|mobile>.png`, в JSON `"nowDrawn": true` - сборка подпишет «пример, нарисовано». В `note` - чего не хватило на проде.
- **Будет** - строго по PRD: разделы 3 и 6, приложение «Текст». Блоков и поведения сверх PRD нет.
- Экран «будет» - экран средней детализации по `roles/product-designer.md`, страница целиком. Скриншот прода - как есть, в цвете. Разница стилей нормальна: сравниваются раскладка, состав и тексты, а место правки показывает пометка.
- Порядок и ширина пары одинаковые: desktop с desktop 1440, mobile с mobile 390.
- В сводке, пунктах и списках правок - короткие фразы, без «допущение», «TBD», вопросов (`prd-template.md`, «Чистый документ»).
- **Нового экрана нет в проде** (решение PO от 11.11.2026) - рисуешь его целиком, как представляешь: вся страница с шапкой, навигацией и контентом, а не фрагмент. Состояния (пусто, ошибка, нет мест, статусы) - каждое отдельным полным экраном в `states`. Слева вместо пустоты - экран прода, с которого пользователь сюда попадает; в JSON `entry` - путь «Экран прода → элемент → новый экран». Экран входа тоже новый - рисуешь его «будет» отдельным экраном и показываешь цепочку.
- Неизменённые экраны не показываешь. Изменён один блок длинной страницы - всё равно страница целиком: видно, где блок стоит.

## Скриншоты прода

Публичная страница - скриптом, из корня проекта:

```bash
node ~/.claude/skills/prd/scripts/render_html.js "https://mashina.kg/<путь>" "<папка материалов>/evidence/now_<S1>_desktop.jpg" 1440 --scale 1 --dismiss "Я согласен"
node ~/.claude/skills/prd/scripts/render_html.js "https://mashina.kg/<путь>" "<папка материалов>/evidence/now_<S1>_mobile.jpg" 390 --mobile --dismiss "Я согласен"
```

- Открой каждый файл и проверь: нужный экран, нет окна региона или cookies, картинки загрузились. Не так - повтори с `--wait 4000`; снова не так - бери скриншот исследователя.
- Лента с подгрузкой бесконечна: снимок обрезается на 6000 px. Нужный блок ниже - `--max-height 9000`. Закреплённые элементы сайта (шапка, плашка приложения на mobile) попадают в снимок один раз - так и должно быть.
- Экран за входом, заявка, состояние после действия - скрипт без сессии их не покажет. Бери скриншоты из `evidence/` исследователя (Full) или снимай `bb-browser screenshot --tab <id>` во вкладке с сессией пользователя (`routing.md`, «Браузер и съёмка»). Только просмотр: формы не отправляешь, кнопки оплаты и публикации не нажимаешь.
- Нет ни одного способа снять - дорисуй «сейчас» как пример (раздел «Правила содержания», `nowDrawn`), в ответе оркестратору строка «сейчас нарисовано: <экран>, <причина>».

## Экраны «будет»

- Full: экраны из `<Фича>.design.html`, рендер тем же `render_html.js` в `evidence/next_<S1>_<desktop|mobile>.png`. Отдельно не рисуешь.
- Lite: рисуешь только изменённые и новые экраны по PRD, HTML в `evidence/next/<S1>_<desktop|mobile>.html`, PNG в `evidence/next_<S1>_<desktop|mobile>.png`. Основа - скриншот прода: та же раскладка, блоки, тексты, плюс изменения из PRD с пометками «новый» и «изменён».
- Для сравнения и прототипа экран рендерится без пометок, плотность 2 (по умолчанию) - фрагменты «крупно» выходят чёткими. То же для дорисованного «сейчас»:

```bash
node ~/.claude/skills/prd/scripts/render_html.js "<папка материалов>/evidence/next/S1_desktop.html" "<папка материалов>/evidence/next_S1_desktop.png" 1440 --no-notes
node ~/.claude/skills/prd/scripts/render_html.js "<папка материалов>/evidence/next/S1_mobile.html" "<папка материалов>/evidence/next_S1_mobile.png" 390 --no-notes
```

- `--no-notes` снимает класс `notes` у `<body>`: все пометки экрана должны рисоваться только при этом классе и исчезать без сдвига раскладки (`roles/product-designer.md`, «Пометки на экране»). Открой PNG и проверь: пометок нет, блоки не съехали, блок-карточка не превратился в текст без границ.

## Пометки правок на кадре

Координаты не подбираешь на глаз - их снимает скрипт с HTML экрана.

1. В HTML экрана «будет» у элемента правки ставишь `data-chg="<номер>"` - номер строки в `changes` этого состояния, с 1. Помечай сам элемент (кнопку, строку текста, тумблер), а блок целиком - только когда новый весь блок.
2. Правка типа `changed` - `data-chg` и в HTML дорисованного «сейчас» (`evidence/now/`), на том же элементе в прежнем виде. Правка типа `removed` - только там, на элементе, который исчезает; элемент спрятан в меню - на кнопке меню. «Сейчас» - скриншот прода: для `changed` координаты измеряются по сетке (ниже), для `removed` пометь на «будет» место, откуда элемент убран.
3. Один элемент на две правки - `data-chg="1,2"`. Один HTML на несколько состояний - `data-chg="S3b:1"` (правка 1 только у состояния `S3b`).
4. Запускаешь из корня проекта:

```bash
node ~/.claude/skills/prd/scripts/ba_marks.js "<папка материалов>/before_after.json"
```

Скрипт открывает HTML в ширине кадра, пишет в JSON `at` (экран «будет») и `atNow` (дорисованное «сейчас») и печатает по каждому состоянию, у каких правок пометки нет. HTML ищется рядом с картинкой: `evidence/next_S1_desktop.png` → `evidence/next/S1_desktop.html`, `evidence/now_S1_mobile.png` → `evidence/now/S1_mobile.html`. Другой путь (Full, общий файл) - поля `nextHtml` и `nowHtml` у платформы. После правки HTML или порядка `changes` запускаешь снова.

Скриншот прода HTML не имеет. Для правки типа `changed` поставь пометку и на нём: читатель видит одно место слева и справа. Координаты измерь по сетке и впиши в `atNow` руками - `[x, y, ширина, высота]` в CSS px кадра:

```bash
node ~/.claude/skills/prd/scripts/ba_grid.js "<папка материалов>/evidence/now_S1_desktop.jpg" 1440 400 700 tmp/grid.png
```

Элемент на скриншоте закрыт плашкой или не найден - пометку на «сейчас» не ставишь, на «будет» она обязательна.

## before_after.json

Лежит в папке материалов. Пути картинок - от папки JSON.

```json
{
  "feature": "Название фичи",
  "date": "12.11.2026",
  "intro": "Одна строка: что меняется для пользователя",
  "summary": [
    { "what": "Срок объявления", "now": "Даты окончания нет", "next": "Блок «Объявление активно до {date}»",
      "type": "new", "screen": "S3", "ref": "3.2, 3.9 · кр. 9" }
  ],
  "outside": [
    { "what": "Пуши и SMS о сроке", "why": "Сайт не меняется. Тексты - PRD, п. 3.8" }
  ],
  "screens": [
    {
      "id": "ad",
      "name": "Страница своего объявления",
      "short": "Объявление",
      "ref": "3.3, 3.9 · кр. 9-12",
      "source": "https://mashina.kg/details/<id>",
      "captured": "12.11.2026",
      "points": [
        "У активного объявления появляется блок срока «Объявление активно до {date}».",
        "С 27-го дня в блоке кнопка «Продлить». Списание сразу, без окна подтверждения."
      ],
      "states": [
        {
          "id": "S3",
          "name": "Активное, дни 1-26",
          "status": "changed",
          "nowDrawn": true,
          "note": "Одна строка, если без неё пара непонятна",
          "platforms": {
            "desktop": { "now": "evidence/now_S3_desktop.png", "next": "evidence/next_S3_desktop.png" },
            "mobile":  { "now": "evidence/now_S3_mobile.png",  "next": "evidence/next_S3_mobile.png" }
          },
          "changes": [
            { "type": "new", "text": "Блок срока: «Объявление активно до {date}»",
              "at": { "desktop": [120, 155, 380, 112], "mobile": [16, 405, 358, 112] } },
            { "type": "changed", "text": "«Поднять» открывает экран продвижения",
              "at": { "desktop": [255, 371, 83, 36], "mobile": [151, 528, 83, 36] } }
          ]
        }
      ]
    }
  ],
  "process": { "title": "Подача объявления", "now": "evidence/process_now.png", "next": "evidence/process_next.png" }
}
```

- `screens[]` - экран, раздел страницы. `states` - его состояния; у экрана с одним состоянием `states` не нужен: `status`, `platforms`, `changes`, `note`, `entry`, `nowDrawn` пишутся прямо в экране. `source`, `captured`, `status`, `entry`, `nowDrawn` состояние берёт у экрана, если своих нет. `id` экранов и состояний не повторяются.
- `short` - короткое имя для шапки, если `name` длиннее трёх слов. Имя состояния - 1-3 слова: «Неактивное», «Не хватает денег».
- `status`: `changed` - обе картинки; `new` - экрана нет в проде: `now` - скриншот прода экрана, откуда переход, `entry` обязателен (без него сборка падает); `removed` - экран убирается, `next` не нужен.
- `nowDrawn`: `true` - картинка «сейчас» нарисована как пример, на проде не снята. Можно у экрана, состояния или платформы (`platforms.mobile.nowDrawn`).
- `changes[].type`: `new`, `changed`, `removed`. `at` и `atNow` - пометка: `[x, y, ширина, высота]` или список таких прямоугольников, если правка видна в нескольких местах. `ref` - пункт PRD у отдельной правки, если он другой, чем у экрана.
- `summary[].type` - тот же набор; `screen` - `id` экрана или состояния, куда ведёт строка; `ref` - пункты раздела 3 и номера критериев раздела 6: `"3.4, 3.6 · кр. 6, 21"`.
- `entryAt` у состояния - место на скриншоте прода, по которому пользователь переходит на новый экран: формат как у `at`, на кадре подпись «вход». Ставит `ba_marks.js` по `data-entry` в дорисованном «сейчас» или пишешь руками по сетке.
- `prototype` - раздел «Прототип», mobile (решение PO от 11.11.2026): экраны «будет» с зонами клика, кнопки «Назад», «В начало», «Показать зоны». Делаешь, когда в фиче больше одного нового или изменённого экрана: путь пользователя от входа на проде до результата и ветки состояний (ошибка, нет мест, успех).
  ```json
  "prototype": { "title": "Прототип: как будет", "start": "P1", "frame": 390,
    "screens": [ { "id": "P1", "name": "Список тарифов", "img": "evidence/next_S1_mobile.png",
      "hotspots": [ { "x": 16, "y": 120, "w": 358, "h": 96, "to": "P2", "label": "Открыть тариф" } ] } ] }
  ```
  Координаты - CSS px внутри кадра шириной `frame` (ширина рендера экрана). Снимай их с HTML экранов «будет» через `getBoundingClientRect` элементов, не на глаз. У каждого экрана хотя бы одна зона, тупиков нет: из конечного экрана - зона «В начало» или назад по смыслу. Картинки - те же, что в `screens`, сборка не дублирует их в файле. Раскрывающиеся блоки (аккордеоны, «Подробнее») - отдельный экран в раскрытом состоянии и зона туда и обратно с `"keepScroll": true`: заголовок, по которому нажали, остаётся на том же месте экрана. Подпись зоны на раскрытом экране - «Свернуть «<заголовок>»», на свёрнутом - «<заголовок>»: по ней скрипт находит тот же заголовок. Нераскрывающийся аккордеон в прототипе - ошибка.
- `prototypeDesktop` - кликабельный прототип desktop (решение PO от 12.11.2026). Тот же формат, `frame` 1440, картинки `next_<S>_desktop.png`, зоны - с desktop-HTML через `getBoundingClientRect`. Делаешь всегда, когда фича есть на desktop-сайте (в `screens` есть desktop-экраны «будет»); только приложение или только mobile web - достаточно `prototype`. На странице прототип переключается кнопкой Desktop / Mobile, кадр desktop ужимается под ширину экрана. Mobile-кнопки без аналога на desktop («‹ Назад» в шапке) не переносишь: назад - кнопкой панели «← Назад».
- `process` - необязательный. Схема «будет» - PNG Excalidraw из раздела 4.
- Старый формат (экраны без `states`, `block` в сводке и правках, нет `at`) собирается, но страница выходит без номеров на кадрах. Пересобираешь старое сравнение - переводи его на этот формат.
