# Сравнение «Сейчас в проде / Будет»

Решение PO от 10.11.2026: в каждом PRD, Lite и Full, рядом с `<Фича>.md` лежит `<Фича>.before-after.html`. По нему за минуту видно, что меняется: слева прод сейчас, справа как будет. Автор - Product Designer. Файл публикуется в Confluence вместе с PRD (`publish.md`, «HTML-вложения»).

## Что внутри

| Часть | Когда | Содержимое |
|---|---|---|
| Сводка | Всегда | Таблица «Что - Сейчас в проде - Будет», 3-10 строк, по строке на изменение из раздела 3 PRD |
| Экраны | Фича меняет или добавляет экран | По экрану: скриншот прода слева, экран «будет» справа, desktop и mobile, список изменений по ID блоков |
| Процесс | Фича меняет шаги, статусы, правила без экрана | Схема или список шагов «сейчас» и «будет» картинками |

Фича без интерфейса (лимиты, логика, админка без макета): сводка обязательна, экранов нет, процесс - если есть схема в разделе 4. Файл всё равно создаётся.

В браузере: переключатель Desktop / Mobile, режим «Рядом» и «Переключать» (один экран на всю ширину, пробел меняет «сейчас» и «будет»), синхронная прокрутка пары, клик по картинке - крупно. Всё делает скрипт, руками HTML не пишешь.

## Правила

- **Сейчас** - только то, что видно на проде `mashina.kg` в день сборки: скриншоты и тексты дословно. Заявки на автофинансирование и лизинг - preprod. Не видел - не пишешь; это допущение в ответ оркестратору.
- **Будет** - строго по PRD: разделы 3 и 6, приложение «Текст». Блоков и поведения сверх PRD нет.
- Экран «будет» - экран средней детализации по `roles/product-designer.md`, страница целиком. Скриншот прода - как есть, в цвете. Разница стилей нормальна: сравниваются раскладка, состав и тексты.
- Порядок и ширина пары одинаковые: desktop с desktop 1440, mobile с mobile 390.
- В сводке и списках изменений - короткие фразы, ID блоков (B1... или C1... для неизменённых блоков прода), без «допущение», «TBD», вопросов (`prd-template.md`, «Чистый документ»).
- Неизменённые экраны не показываешь. Изменён один блок длинной страницы - всё равно страница целиком: видно, где блок стоит.

## Скриншоты прода

Публичная страница - скриптом, из корня проекта:

```bash
node ~/.claude/skills/prd/scripts/render_html.js "https://mashina.kg/<путь>" "<папка материалов>/evidence/now_<S1>_desktop.jpg" 1440 --scale 1 --dismiss "Я согласен"
node ~/.claude/skills/prd/scripts/render_html.js "https://mashina.kg/<путь>" "<папка материалов>/evidence/now_<S1>_mobile.jpg" 390 --mobile --dismiss "Я согласен"
```

- Открой каждый файл и проверь: нужный экран, нет окна региона или cookies, картинки загрузились. Не так - повтори с `--wait 4000`; снова не так - бери скриншот исследователя.
- Лента с подгрузкой бесконечна: снимок обрезается на 6000 px. Нужный блок ниже - `--max-height 9000`. Закреплённые элементы сайта (шапка, плашка приложения на mobile) попадают в снимок один раз - так и должно быть.
- Экран за входом, заявка, состояние после действия - скрипт без сессии их не покажет. Бери скриншоты из `evidence/` исследователя (Full) или снимай `bb-browser screenshot --tab <id>` во вкладке с сессией пользователя (`routing.md`, «Браузер и съёмка»). Только просмотр: формы не отправляешь, кнопки оплаты и публикации не нажимаешь.
- Нет ни одного способа - экран в JSON без `now`, а в ответе оркестратору строка «нет скриншота прода: <экран>, <причина>». Сборка остановится: это блокер, его решает оркестратор.

## Экраны «будет»

- Full: экраны из `<Фича>.design.html`, рендер тем же `render_html.js` в `evidence/next_<S1>_<desktop|mobile>.png`. Отдельно не рисуешь.
- Lite: рисуешь только изменённые и новые экраны по PRD, HTML в `evidence/next/`, PNG в `evidence/next_<S1>_<desktop|mobile>.png`. Основа - скриншот прода: та же раскладка, блоки, тексты, плюс изменения из PRD с пометками «новый» и «изменён».

## before_after.json

Лежит в папке материалов. Пути картинок - от папки JSON.

```json
{
  "feature": "Название фичи",
  "date": "10.11.2026",
  "intro": "Одна строка: что меняется для пользователя",
  "summary": [
    { "block": "B2", "what": "Кнопка связи", "now": "Только «Показать телефон»", "next": "«Позвонить» и «Написать» рядом" }
  ],
  "screens": [
    {
      "id": "S1",
      "name": "Карточка объявления",
      "status": "changed",
      "source": "https://mashina.kg/details/<id>",
      "captured": "10.11.2026",
      "note": "Одна строка, если без неё пара непонятна",
      "platforms": {
        "desktop": { "now": "evidence/now_S1_desktop.jpg", "next": "evidence/next_S1_desktop.png" },
        "mobile":  { "now": "evidence/now_S1_mobile.jpg",  "next": "evidence/next_S1_mobile.png" }
      },
      "changes": [
        { "block": "B2", "type": "changed", "text": "Две кнопки вместо одной" },
        { "block": "B5", "type": "new", "text": "Блок «Проверка по номеру»" }
      ]
    }
  ],
  "process": { "title": "Подача объявления", "now": "evidence/process_now.png", "next": "evidence/process_next.png" }
}
```

- `status`: `changed` - обе картинки; `new` - экрана нет в проде, `now` не нужен; `removed` - экран убирается, `next` не нужен.
- `type` в `changes`: `new`, `changed`, `removed`.
- `process` - необязательный. Схема «будет» - PNG archify из раздела 4.

## Сборка и проверка

```bash
node ~/.claude/skills/prd/scripts/build_before_after.js "<папка материалов>/before_after.json" "<спринт>/<Фича>.before-after.html"
```

Скрипт встраивает картинки, адрес прода пишет текстом без ссылки и останавливается, если нет файла, сводки или картинки «сейчас» у изменённого экрана. Затем открой готовый файл рендером `render_html.js ... 1440` в `tmp/` и посмотри PNG: сводка читается, пары стоят рядом, картинки не пустые. Не проверил - так и напиши в ответе.

Файл больше 15 МБ - пересними прод в `.jpg` с `--scale 1` для desktop.
